Assessment · AI off

Supervised check · 45 minutes

Paper only: no laptop, no assistant. Shell commands, then five commit graphs to draw.

Five minutes of briefing first: what is allowed (a pen), how the graphs are drawn (one circle per commit, an arrow to its parent, branch labels in boxes, HEAD marked). The paper and its key are in the trainer pack, never in the repository. Pass mark on the check: 60%; LO1's evidence is four of the five graphs correct.

Walk through each criterion with what full marks look like: a README a stranger follows without asking; the checksum line printing OK on the peer's workspace; a container that runs as a user that is not root; a scan of every commit that comes back empty; the log merged through a reviewed pull request. The rubric is 40% of the course; the oral (10%) and the labs (30%) are graded apart, so nothing here counts twice.
Pairs

You reproduce one peer's project; a different peer reproduces yours

  • Pairs run in a ring: A reproduces B, B reproduces C, and so on, so no two people check each other
  • The reproducer works on a clean workspace, never on the author's laptop
  • The author does not help during the reproduction: the README speaks for them

Self-test first, 35 minutes

Clone your own repository into an empty folder, follow your README word for word, and fix what you find. After this, no more commits until the handback.

The ring stops two people trading favours. The freeze matters: the reproduction must be of a fixed commit, so ask each author to post the commit id they want reproduced.

Do not repair it for them. When a step fails, record the exact command and the last line of the error, then try the smallest guess and record that too.
The log template is labs/capstone/REPRODUCTION_LOG.md: one row per step, with the command, what the README said, what happened and the last line of any error. A step the reproducer had to guess counts as failed, even if the guess worked: the README did not say it.
Peer reproduction

Reproduce · 150 minutes

Only the README. Log every step. Ask the trainer, never the author.

Walk the room. When a reproducer is stuck for more than ten minutes on one step, tell them to log it as failed and move to the next part (the container, the scan), so the rest of the rubric can still be scored.
Log and handback · 40 minutes

The log arrives as a pull request, and the author merges it after review

  • The reproducer adds reproduction/peer-1.md on a branch and opens a pull request
  • The author reviews it: questions in comments, no edits to the peer's findings
  • Merged by pull request, the log is part of the history the rubric reads

Fix clinic, 70 minutes

Each author starts on the failed steps, one small commit per fix, each through a pull request. The trainer takes questions at the front.

Twenty minutes to write the log, twenty for the handback and review. In the fix clinic, nudge authors towards the smallest fix that makes the README true, not a rewrite. The follow-up task (60 minutes, guided self-study) finishes the fixes; the same peer then records a second reproduction as peer-2.md.

2 · Why

What the README assumed that the clean workspace did not have.

3 · The fix

The commit that fixed it, and the line of the second log that proves it.
